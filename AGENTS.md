# studyAI engineering scope

Stages 1–5 are the local desktop portfolio MVP. Preserve PDF/text processing, real TF-IDF retrieval, local Ollama practice/feedback, and the persistent dashboard. Keep the saved-materials library visibly unfinished. Future features require a new user request.

Use loopback services and bounded RAM sessions. Close upload handles; original documents must not become a permanent server store. Browser localStorage holds validated submitted records, summaries, theme preferences, and bounded source excerpts. Exclude original PDFs, full lecture input, and unsubmitted keys.

Keep TypeScript strict, components focused, and FastAPI routes thin. Preserve technical notation/source metadata. Use real PyMuPDF/scikit-learn operations. Read README.md when changing setup, limits, lifecycle, or scoring. One backend process owns temporary sessions.

Keep keys private until submission. Lock answers/reasoning before inference; feedback retries preserve answers. Numerical scores compare selected/stored indices only. Display subjective feedback and topic estimates separately. Recompute cached summaries and disclose storage/retention errors. Model-assessed understanding is an estimate, not a diagnosis.

Send fixed system instructions and JSON-encoded untrusted evidence to Ollama. Validate JSON and resolve citations from supplied passage IDs. Never fabricate product AI outputs, references, similarity values, confidence, or metrics. Demo notes are original/labeled; mock responses belong only in tests.

After functional changes, run backend Pytest/health and frontend tests, HTTP integration, typecheck, and build. Read docs/TESTING.md for real-model/visual acceptance and environment blockers. Distinguish real NLP, mock inference, and actual model testing. Read docs/GITHUB_CHECKLIST.md before publication; the user requires approval before pushing.
